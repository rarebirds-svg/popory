# popory Portal 리브랜딩 — 디자인 스펙

작성일 2026-05-31 · 상태 합의 완료(구현 계획 대기)

## 1. 배경과 목표

popory portal은 Next.js 15 + React 19 + Tailwind 기반의 가족용 통합 진입점이다. 현재는 기능 우선의 미니멀 라인 UI로, 시각적 위계와 브랜드 개성이 약하다. 매일 오전 9시 발행되는 일일 브리핑(부동산 외 다수 카테고리)이 핵심 콘텐츠이며, 이를 "읽고 싶게" 만드는 것이 리브랜딩의 1차 목표다.

**한 줄 컨셉.** 고급 매거진처럼 읽히는 일일 브리핑 포털.

**성공 기준.**
- 공개 표면(랜딩·대시보드·브리핑 허브·목록·본문)이 하나의 에디토리얼 디자인 언어로 통일된다.
- 브리핑 본문이 30초 안에 스캔 가능한 구조(키커 → 헤드라인 → 요점 카드 → "왜 중요한가")를 갖는다.
- 라이트/다크 양 모드가 모두 정제된 상태로 동작한다.
- 기존 라우트·API·데이터 흐름은 건드리지 않는다. 순수 프레젠테이션 레이어 교체.

## 2. 두 개의 디자인 언어

전체 리브랜딩이되, 표면 성격에 따라 두 결을 쓴다. 공개 영역은 독자를 위한 밝고 스캔 가능한 톤, 백오피스는 운영자를 위한 차분한 에디토리얼 톤으로 의도적으로 분리한다.

### 2-A. 공개 표면 — "The Brief" (Axios / Semafor 계열)

- **강조색** 네이비 `#1f3a93` (라이트), 다크에서는 `#6f8bdc` 류로 밝힌다.
- **타이포** 헤드라인은 세리프 Fraunces, 본문/UI는 산세리프 Inter + Noto Sans KR. (목업에서 검증한 조합.)
- **구성 요소** 키커(accent-soft 배경 칩), 요점 카드(좌측 4px accent 보더), "왜 중요한가" 강조 블록, 날짜 중심 목록.
- **적용 화면** 랜딩(`/`), 대시보드(`/dashboard`), 브리핑 허브(`/p/brief`), 영역 목록(`/p/[area]`), 본문(`/p/[area]/[id]`), 공개 아카이브 홈(`/p`).

### 2-B. 어드민 표면 — "The Ledger" (Monocle / Kinfolk / Stripe Press 계열)

- **무드** 따뜻한 종이 톤 배경, 세리프 헤드라인, 잉크 레드 포인트, 2단/표 기반의 차분한 매거진 레이아웃.
- **목적** 운영 화면을 "장부(ledger)"처럼 정제되고 집중된 공간으로. 공개 영역과 시각적으로 명확히 구분.
- **적용 화면** 어드민 대시보드(`/admin`), 화이트리스트(`/admin/whitelist`), 사용자(`/admin/users`), 카테고리 목록/생성/편집(`/admin/brief-categories/*`).

두 언어는 **같은 토큰 시스템과 폰트 자산**을 공유한다. 차이는 토큰 값(색·배경)과 컴포넌트 조합에서 나온다. 완전히 분리된 두 디자인 시스템이 아니라, 하나의 기반 위 두 테마다.

## 3. 토큰 아키텍처

현재 `packages/ui/src/components/tokens.css`는 6개 변수(`--popory-bg/fg/muted/accent/card/border`)를 라이트/다크로 정의하고, `tailwind.config.ts`가 이를 색으로 매핑한다. 이 구조를 확장한다.

**확장 방침.**
- 기존 6개 변수는 유지하되 값을 에디토리얼 팔레트로 재조정한다.
- 추가 토큰. `--popory-accent-soft`(키커·블록 배경), `--popory-ink2`(본문 보조 텍스트), `--popory-ledger-bg`/`--popory-ledger-fg`/`--popory-ledger-accent`(어드민 종이 톤 계열).
- 라이트/다크는 현재처럼 `@media (prefers-color-scheme)`로 자동 전환. (수동 토글은 범위 밖.)
- 폰트는 `next/font`로 Fraunces(또는 Newsreader)·Inter·Noto Sans KR을 root layout에서 로드하고 CSS 변수로 노출. 어드민은 동일 폰트 자산에서 세리프 비중을 높여 조합.

Tailwind에는 새 토큰을 색/폰트로 매핑하는 항목만 추가한다. 유틸리티 우선 접근을 유지한다.

## 4. 컴포넌트 설계

`packages/ui`에 공유 프리미티브를 두고, 표면별 조합은 각 페이지에서 한다. 신규 컴포넌트는 단일 책임·명확한 props를 갖는다.

### 공유(@popory/ui) 신규/개편
- `Kicker` — accent-soft 배경의 카테고리/날짜 칩.
- `BriefCard` — 요점 카드(제목 + 불릿), 좌측 accent 보더 변형 포함.
- `WhyBlock` — "왜 중요한가" 강조 블록.
- `Nav` — 기존 `Header.tsx` 개편. 로고(dot 마크) + 우측 메뉴/사용자.
- `Card.tsx` — 유지하되 새 토큰에 맞춰 스타일 조정.
- `MarkdownBody.tsx` — `prose-popory` 재설계(본문 폭·행간·소제목·인용 위계). 브리핑 본문이 마크다운이므로 이 컴포넌트가 본문 읽기 품질을 좌우한다.

### 공개 표면 페이지 조합
- 대시보드 — 인사말 헤더 + 오늘 발행 현황을 얹은 서비스 카드 그리드(브리핑은 피처 카드).
- 브리핑 허브 — 카테고리 카드(이름·발행 수·최신 미리보기). `/api/brief-categories` 동적 카테고리 유지.
- 목록 — 날짜(일/월) 중심의 스캔형 리스트.
- 본문 — 키커 → 세리프 헤드라인 → 메타(읽는 시간) → 마크다운 본문. 요점 카드/Why 블록은 본문이 해당 구조일 때 자연스럽게 렌더.

### 어드민 표면 페이지 조합
- `admin/layout.tsx`에 Ledger 테마 컨테이너(종이 톤 배경·세리프 헤딩)를 적용해 어드민 전체에 일괄 입힘.
- 폼(`EditForm`/`NewForm`)·테이블(users/whitelist)은 Ledger 톤의 input/table 스타일로 재조정. 기능·Server Action은 불변.

## 5. 범위와 비범위

**범위.** 위 토큰·공유 컴포넌트·공개 6개 화면·어드민 5개 화면의 프레젠테이션 교체. 라이트/다크 양 모드. 폰트 도입.

**비범위.** 라우팅·인증·세션·API·데이터 모델 변경. 신규 기능(검색·댓글 등). 수동 다크모드 토글. 브리핑 생성 자동화(launchd/CLI) 변경.

## 6. 데이터 흐름·에러 처리

데이터 흐름은 현행 유지. 페이지는 기존처럼 `/api/brief-categories`, `/api/published_items` 등을 호출하고 결과를 새 컴포넌트로 렌더한다. 빈 상태(발행물 0건)·로드 실패 시의 표시를 각 표면에서 정제된 빈 상태(empty state) UI로 다룬다 — 현재는 이 처리가 빈약하므로 리브랜딩에 포함한다.

## 7. 검증

- 빌드. `next build`가 통과한다.
- 시각. 6개 공개 화면 + 5개 어드민 화면을 라이트/다크에서 직접 확인(스크린샷 또는 로컬 실행).
- 회귀. 기존 라우트가 그대로 동작하고 API 호출/데이터가 변하지 않았는지 확인.
- 반응형. 모바일/데스크톱 폭에서 그리드·본문 폭이 깨지지 않는지 확인.

## 8. 단계 제안(구현 계획에서 구체화)

1. 토큰·폰트 기반 확장(`tokens.css`, `tailwind.config.ts`, root layout) → 빌드 통과.
2. 공유 컴포넌트(Kicker/BriefCard/WhyBlock/Nav, MarkdownBody·Card 개편).
3. 공개 표면 적용(랜딩 → 대시보드 → 허브 → 목록 → 본문).
4. 어드민 Ledger 테마 적용(layout → 폼·테이블).
5. 라이트/다크·반응형·빈 상태 점검 및 정리.

각 단계는 독립적으로 빌드·확인 가능하도록 끊는다.
