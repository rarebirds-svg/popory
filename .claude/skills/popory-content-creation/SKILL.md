# 포포리 책방 콘텐츠 생성 피드백

## 개요

popory `services/content`가 한 주제로 4개 채널(블로그·유튜브 동영상·쇼츠·인스타 캐러셀) 콘텐츠를 claude CLI + 로컬 imagegen + TTS로 생성한다. 채널 브랜드는 **포포리 책방 — 한 권의 책에서 길어올린 인생의 지혜**. 이 문서는 그동안 생성 결과를 보며 주고받은 피드백을 모은 단일 레퍼런스다. 규칙은 `prompt.py`(블로그)·`video_prompt.py`(유튜브·쇼츠)·`instagram_image_prompt.py`(캐러셀)·`tts.py`(내레이션 음성)·`video.py`(조립)에 반영돼 있다.

## 언제 사용

- 콘텐츠 생성 프롬프트(`*_prompt.py`)나 TTS·영상 조립 코드를 수정할 때.
- 생성물 검토 중 "왜 이렇게 나오지/이건 안 됐었는데" 판단이 필요할 때.
- 새 채널·옵션을 추가할 때 기존 합의 사항을 깨지 않으려 할 때.

## 공통 원칙 (모든 채널)

- **사실 우선.** WebSearch·WebFetch로 신뢰 자료 수집, 사용자 참고 링크 반영, **확인된 사실만**. 근거 부족 시 추측 금지.
- 자연스러운 한국어 구어체. **문장은 마침표로 끝낸다** (콜론 종결 금지). 단 영상 내레이션(유튜브·쇼츠)은 **물음표 종결도 허용** — 아래 어미 다양화 규칙 참조.
- **간투사·추임새 금지** — '음·어·아·그' 같은 의미 없는 말은 대본·내레이션에 쓰지 않는다.
- 스타일 프로필 샘플이 있으면 그 어조·문장 길이·표현을 따른다.
- 출력은 항상 지정된 두 태그(예: `<scenes_json>`/`<video_meta>`)를 정확히 포함하고, 태그 안엔 ``` 코드블록 표시를 넣지 않는다.
- **외국 저자명은 국내 출판 표기를 쓴다** — 국립국어원 외래어표기법이 아니라 **책 표지에 박힌 표기**다. 독자가 검색창에 치는 게 그쪽이고, 제목의 인명이 틀리면 검색 유입이 통째로 날아간다. 2026-08-23 발행분에서 Bodo Schäfer 가 `보도 새퍼`(정: `보도 섀퍼`)로 나가 제목·대본·태그가 함께 오염됐다. 안전망으로 `names.py` 의 교정표가 claude 출력 길목(`run_claude_cli`)에서 한 번, 추천→주제 등록 직전(`auto_create`)에서 한 번 걸린다 — 후자는 교정 이전에 포털에 쌓인 행을 잡기 위한 것이다. **교정표에 새 항목을 추측으로 넣지 말 것** — 서점 상세페이지로 확인한 표기만 넣는다. 출판사마다 갈리는 이름(말콤/맬컴 글래드웰)은 어느 쪽도 오타가 아니므로 넣지 않는다.

## CTA·브랜딩 규칙 (채널별로 상반되니 주의)

| 채널 | 구독/좋아요/팔로우 유도 | 마무리 |
|------|------------------------|--------|
| 유튜브 롱폼 | **마지막 장면(엔딩 CTA)에만 허용** — 구독·좋아요 → 댓글 질문 → "화면에 보이는 추천 영상" 3단계(2026-09, 시청 지속·구독 전환 개선). 본문 장면 내레이션엔 여전히 금지. LLM 이 빠뜨리면 `video_contract.ensure_ending_cta` 가 `video_prompt.ending_cta_scene()` 을 결정적으로 덧붙인다. **채널의 다른 영상 제목은 지어내지 않는다**(종료 화면은 업로드 후 붙는다). description 구독 CTA 허용 | description은 요약만 생성 → `parse_video`가 구독 링크(정확한 채널 ID)+브랜딩을 **결정적 append** |
| 쇼츠 | 내레이션·마무리 **절대 금지**(60초 안에 CTA 없음). `parse_video(ending_cta=False)` | description CTA 는 롱폼과 동일 |
| 블로그 | 해당 없음 | 출처 표기·SEO 우선 |
| 인스타 캐러셀 | **팔로우 유도 OK** (첫·마지막 슬라이드) | caption 해시태그 포함 |

영상 description은 내용 2~3문장(쇼츠는 1~2문장) 요약만 생성한다. 구독 링크·브랜딩 줄은 프롬프트가 아니라 `video_contract.parse_video`가 `append_description_cta`로 붙인다(LLM이 URL을 지어내 깨지는 것 방지). 구독 URL은 `video_prompt.CHANNEL_SUB_URL`(`?sub_confirmation=1`).

**제목(title)은 훅을 앞, 책 제목을 뒤에** 둔다(`{훅} — {책제목}`, 앞 15자 훅). 예 `140억을 만든 한 문장 — 피터 린치`. (2026-07 CTR 개선. 이전엔 형식 규칙 없어 책 제목이 앞서곤 했다.)

**데일리 주제 큐레이션은 투자·돈·경제 ~60% 비중**(`recommend_weekly.py`). 채널에서 투자 주제 조회수가 1위라 가중.

**업로드 영상은 주제별 재생목록 자동 분류**(`youtube_playlist.py`). 제목·태그 키워드로 4버킷(투자·경제 / 자기계발·습관 / 인문·철학 / 시·에세이, 미분류는 기본) → find-or-create → 추가. `run_upload_once`에서 호출, `POPORY_YOUTUBE_PLAYLISTS=0`으로 끔. 실패해도 업로드 done 유지.

## 채널별 규칙

### 블로그 (네이버) — `prompt.py`
- **제목은 검색어가 앞, 말머리 금지(2026-09-06 제미나이 검토 반영)** — 네이버·구글 검색 봇은 제목의 **가장 왼쪽(첫 15자)** 에 가장 높은 키워드 가중치를 준다. `[책 리뷰] 사이토 히토리,1퍼센트 부자의 법칙:…` 처럼 검색자가 치지 않는 말머리가 앞단을 차지하면 책·저자가 뒤로 밀린다. 형식은 `{저자} {책제목} 핵심 요약 및 서평: {핵심 메시지 한 줄}` 이고 롱테일어(핵심 요약·서평·줄거리·책 추천) 1~2개를 앞부분에 결합한다(예. `사이토 히토리 1퍼센트 부자의 법칙 핵심 요약 및 서평: 말버릇 하나로 인생을 바꾸는 1천 번의 법칙`). 60자 안팎. 핵심 검색어는 `meta.keyword` 에 따로 남긴다. 안전망으로 `seo_title.strip_prefix` 가 검토기의 `revised_title` 과 워커의 최종 `meta.title` 두 길목에서 `[책 리뷰]`·`서평:` 류 말머리를 걷어낸다 — 제목을 새로 짓지는 않는다(걷어내고 남는 게 없으면 원문 유지).
- **소제목(H태그)은 개수 규칙이 있다** — 본문 600~800자마다 `<h2>`/`<h3>`, 글 전체 5~8개. 6,000~14,000자 글에 H태그 0개, 볼드만 있던 게 검토에서 잡혔다(볼드는 검색 봇에 소제목이 아니고 스마트블록·스니펫은 H태그 단위로 가져간다). 검토기(`seo_review.py`)는 굵은 `<p>` 소제목을 `<h3>` 로 바꾼다.
- **키워드 배치 4~6회** — 핵심 검색어를 도입 3줄 이내 1회, 관련 소제목마다 1회, 결론부 1회. 그 이상은 스터핑 감점.
- **이미지 alt·figcaption(사진 설명)에 검색어** — 책 리뷰는 이미지가 10~30장인데 '사진 설명' 이 비어 있었다. 네이버 이미지 검색 유입은 사진 설명에서 나온다. `<figcaption>검색어가 든 설명 · 출처: 매체 (링크)</figcaption>` 형식. "이미지"·"사진 1" 같은 빈 설명 금지. 네이버 발행 단계(`publish_browser.py`)도 사진마다 **'사진 설명 입력' 란에 alt 를 넣고**, 모든 h2/h3 에 툴바 **'소제목' 스타일을 지정**하며 개수를 원고와 대조한다.
- **SEO·AEO·GEO 구조가 프롬프트에 박혀 있다(2026-09)** — 첫 문단은 핵심 질문의 직접 답(2~3문장), 질문형 소제목 일부, `<h2>자주 묻는 질문</h2>` + `<h3>Q</h3><p>A</p>` 3개, 수치·인명엔 문장 안 출처, 단락마다 인용 가능한 완결 문장, 핵심 개념 정의문, 모든 `<img>` 에 alt.
- **생성 직후 `seo_review.py` 가 검토·교정한다** — claude CLI 가 SEO/AEO/GEO 축별 0~100 점수·문제 목록과 교정본을 낸다. 교정본은 **원문의 70% 이상 길이이고 script/style 이 없을 때만** 채택(`accept_revision`) — 검토기가 글을 잘라먹는 것보다 원문이 낫다. 결과는 `meta.seo_review`(포털 `SeoReviewPanel` 표시), 로그 `seo_reviewed`/`seo_review_error`. 유튜브 커뮤니티 글도 같은 경로(`review_youtube_post`)를 탄다. fail-open, `POPORY_SEO_REVIEW=0` 으로 끔.
- **비공개 발행(`publish_browser.py`)** — 사용자가 포털 `/content/publish` 에서 블로그(네이버/티스토리)·유튜브 커뮤니티를 설정하면 review 전이 시 `/result` 가 `publish_status='requested'` 를 찍고(자동 발행 켜진 경우), 워커가 `run_publish_once` 로 claim 해 **aside 브라우저 스킬**(`/aside-browser`, `POPORY_BROWSER_SKILL`)을 claude CLI 로 호출한다. **이 스킬은 MCP 도구**(`mcp__aside__exec`·`mcp__aside__memory_search` 등)**로 움직인다** — 스킬 안내문의 `aside "..."` 는 사람에게 보여 주는 설명이지 호출 경로가 아니다. 그 문구만 보고 허용 도구를 `Bash(aside:*)` 로 바꿨더니 MCP 도구가 목록에서 빠져 "권한 승인을 받지 못했다"로 시작조차 못 했다(2026-09-05). 기본값 `POPORY_BROWSER_TOOLS=Skill,mcp__aside,mcp__aside__*,Bash(aside:*),Read` 는 aside MCP 서버 전체를 연다. 허용 문법은 `mcp__<server>`(그 서버 전체) 또는 `mcp__<server>__*`(같은 뜻) 이고, allow 규칙의 글롭은 서버 이름 뒤에서만 먹는다. 지시문은 항상 **비공개**를 강제하고, 유튜브 커뮤니티는 비공개 옵션이 없어 30일 뒤 예약(`POPORY_YOUTUBE_POST_SCHEDULE_DAYS`)으로 올리며 예약도 안 되면 `skipped`. 스킬이 공개로 올렸다고 보고하면 성공으로 기록하지 않는다. **성공 보고도 본문 대조를 통과해야 done 이다** — 2026-09-05 티스토리에 제목·태그만 들어가고 본문이 빈 글이 "등록 완료" 로 보고됐다(편집기 모드 전환이 본문을 날렸는데 확인을 안 했다). 발행 자체는 성공하므로 이 대조가 없으면 빈 글이 완료로 남는다. 성공 보고에 `body_chars`(편집기에서 확인한 본문 글자 수)를 요구하고 `check_body` 가 원고의 태그 제거 길이와 견줘 `POPORY_PUBLISH_MIN_BODY_RATIO`(기본 0.5) 미만이거나 미보고면 failed 로 돌린다. 이때 오류는 **새로 올리지 말고 그 글을 고치라**고 안내한다 — 글은 이미 올라가 있어 재시도가 곧 중복이다. 티스토리 단계는 **본문 입력 전에 HTML 모드로 전환**하고 그 뒤 기본 모드로 되돌리지 않는다(되돌리면 본문이 날아간다). 중복 게시 방지로 CLI 재시도 없음(`MAX_ATTEMPTS=1`), 리스 20분. **재시도가 없으므로 결과 태그 파싱은 관대해야 한다** — 실패하면 글이 올라갔는지조차 모르는 상태로 굳는다(2026-09-05 "publish_result 태그 없음"). `parse_publish_result` 가 태그 안 코드블록·닫는 태그 누락·태그 자체 누락(본문에 JSON 만 남은 경우)까지 읽고, 그래도 실패하면 오류에 **중복 게시 경고**(글 목록·임시저장 먼저 확인)를 붙인다. `run_claude_cli` 는 파싱 실패 시 모델 출력 꼬리(`POPORY_PARSE_FAIL_TAIL`, 기본 800자)를 오류에 실어 준다 — 이걸 버리면 진단이 통째로 불가능하다. 스킬 호출 규약이 다르면 `POPORY_PUBLISH_CMD`(stdin 작업 JSON → stdout `<publish_result>`)로 갈아끼운다. 스킬 이름은 맥미니에서 `/aside-browser` 로 확인됐고, **등록 범위는 user** 다(`claude mcp get aside` → "User config (available in all your projects)", 2026-09-05). 그래서 **워커의 cwd 는 상관없다** — 발행 실패의 실제 원인은 허용 목록에서 `mcp__aside` 가 빠진 것 하나였다. `POPORY_PUBLISH_CWD` 는 기본이 비어 있고(워커 cwd 상속), **local 범위로 등록된 환경에서만** 그 디렉터리를 지정한다 — local 등록은 디렉터리마다 따로라(`~/.claude.json` 의 `projects.<path>.mcpServers`) 그 밖에서 띄운 claude 엔 서버가 아예 없다. **launchd 는 최소 PATH 로도 워커를 띄운다** — `run_worker.sh` 가 `/opt/homebrew/bin` 등을 PATH 에 넣어 준다(generate.py 가 claude 를, video.py 가 ffmpeg 를 절대경로로 하드코딩해 온 것과 같은 이유). 발행이 브라우저에 닿지도 못하고 죽으면 원인은 거의 항상 허용 도구 아니면 PATH 다 — `_setup_hint` 가 실패 사유에서 그 신호를 읽어 고칠 곳을 `publish_failed` 로그에 한 줄로 붙인다.
- 시맨틱 **HTML 조각**만 출력 (`<h2><h3><p><ul><blockquote><table>`). `<html>·<body>·<script>·<style>` 래퍼 금지.
- 이미지 2~4장 임베드. `<figure><img><figcaption>출처: 매체 (링크)</figcaption>` — **출처 표기 필수**, 출처 모르면 넣지 않음.
- 관련 YouTube 1~2개 임베드 (`youtube-nocookie`, **실제 존재 영상만**).
- SEO: 핵심 키워드를 `<h2>`·첫 문단에 자연 배치. 원문 길게 복붙 금지(패러프레이즈). 사실·수치·인용·이미지·영상 출처 표기.

### 유튜브 동영상 — `video_prompt.py`
- 장면(scene) 약 N개 — **기본 16장면**(`DEFAULTS`의 `length: "10"` → `SCENE_COUNT["10"]`). 길이 옵션은 `3→5 / 5→8 / 7→12 / 10→16`장면이다. 각 장면 = caption(16자 이내 핵심 헤드라인, 공백 포함 기준) + narration + image_prompt(영어, 글자 없음).
- **각 장면 narration은 소리 내어 ~35초(보통 5~7문장)** 로 충분히 풀어 쓴다. 짧으면 영상이 설정 길이보다 짧아짐 → 사례·설명·맥락으로 채운다.
- **프리후크 → 본문 → 여운 → 엔딩 CTA (2026-09 대표 영상 검토 후 개편).** 첫 장면은 서정적 배경 대신 **첫 문장에 충격적 결론·대비**를 던지고 "오늘 영상에서는 …을 정리해 드립니다"로 예고한다(시청자 30~50%가 첫 15초에 이탈 여부를 정한다). 본문은 3~4장면마다 한 문장 요약("여기까지 정리하면, …")과 청자에게 직접 던지는 질문을 넣는다. 마지막 장면은 위 CTA 표의 3단계다.
- **카드 장면 2~3개** — 장면 JSON 의 선택 필드 `card`: `{"type":"quote","text":"…","source":"…"}`(확인된 문장만, 아니면 source 비움) 또는 `{"type":"keypoints","title":"…","items":[…2~4개]}`. `video_contract.normalize_card` 가 모양이 틀리면 조용히 버린다(카드는 장식이지 대본이 아니다). `video.py` 가 그 장면 **앞에** 어두운 배경의 카드 클립(`CARD_SECONDS` 3.5초, `_card_clip`)을 끼운다 — 오디오는 `assets/sfx/chime.mp3` 가 있으면 차임, 없으면 무음(24kHz 모노로 맞춰 acrossfade 가 깨지지 않게). 카드 클립은 cue 를 만들지 않으므로 `scene_local_cues` 에 빈 목록을 같이 넣어 자막 오프셋 짝을 유지한다. 끄려면 `POPORY_CARDS=0`.
- **대본 오탈자·고유명사 검수(`script_review.py`)** — `make_video` 가 렌더 전에 claude CLI(WebSearch 허용)로 치환 목록(`from→to`)만 받아 장면·제목·태그·설명·카드에 일괄 적용한다. 대본을 다시 쓰게 하지 않는 이유는 어미 다양화·길이·CTA 규칙이 무너지기 때문. from 이 대본에 실제로 없거나 1글자면 무시. fail-open 이며 결과는 `meta.script_review`(`status: ok|unavailable|disabled`). 배경: 2026-09 발행분에서 `버몬트→범트`·`구제 옷가게→구제욱가게`·`부→불` 이 자막·TTS 로 나갔다. `names.py` 교정표는 아는 오타만 잡는다.
- **어미 다양화 (2026-08 톤 단조로움 개선)** — TTS가 문장별로 독립 합성되므로(`video.py` `_split_sentences`→`synthesize`) 어미가 같으면 모든 문장이 동일한 종결 억양(하강조)으로 끝나 기계적으로 들린다. 대응: ① 합쇼체(~습니다) 기본에 해요체 종결(~죠·~거든요·~인데요·~예요) 혼용, ② '-ㅂ니다/-습니다' **3문장 연속 금지**, ③ 장면당 1문장 정도 수사 의문문(**물음표 종결** — 물음표가 있어야 TTS가 상승조를 붙인다). 쇼츠에도 축약 적용. 문장 분할 regex(`[.?!]`)·자막 파이프라인은 물음표를 이미 처리한다. 이걸로 부족하면 다음 단계는 장면 단위 통합 합성(+v1beta1 `<mark>` 타임포인트)이나 Chirp3-HD 남성 화자 A/B(Charon 제외 — 두 번 기각 이력).

## TTS (영상 내레이션) — `tts.py`
- 기본 음성 **`ko-KR-Neural2-C`(남성)** — `options.py`의 `VOICE["male"]`, `DEFAULTS`가 `voice: "male"`. 선택지 `female-calm`=`ko-KR-Chirp3-HD-Aoede`, `female-bright`=`ko-KR-Chirp3-HD-Leda`. pitch는 아예 보내지 않는다(모델 기본값). **남성만 Neural2, 여성 둘은 Chirp3-HD**로 계열이 섞여 있다.
- **말속도 `SPEAKING_RATE`는 화자 계열과 짝이 맞아야 한다** — **1.0 = Neural2 기준값, 1.06 = Chirp3-HD 기준 귀 튜닝값**이다. 기본 화자가 Neural2-C이므로 현재 **1.0**(`POPORY_TTS_SPEAKING_RATE`로 튜닝). 화자를 Chirp3-HD 계열로 바꾸면 이 값도 1.06으로 **함께** 올릴 것. `test_speaking_rate_matches_default_voice_family`가 이 짝을 강제한다.
- **한쪽만 바뀌면 실제로 깨진다(재발 사례)** — `cb48d04` 머지에서 `options.py`는 Neural2-C인데 `tts.py`만 1.06으로 남아, 내레이션이 **Neural2-C를 Chirp3-HD용 속도로** 읽었다. PR #5(Charon 복귀 + 1.06) 브랜치가 `aae6588`(Charon→Neural2-C 취향 복귀)보다 먼저 갈라져 나왔는데 나중에 머지돼 섞인 결과다. 화자·속도를 건드리는 브랜치가 둘 이상 살아 있으면 **머지 후 두 파일을 같이 확인할 것.**
- **말속도 튜닝 이력** — 0.96이 "살짝 쳐지는 느낌"이라 `294f614`(2026-06-26)에서 콤마 break 단축(350→175ms)과 **한 세트로** 1.06으로 올렸다. `f8e2898`(06-29)에서 1.0으로 내린 건 같은 날 기본 음성을 Charon→Neural2-C로 되돌린 것과 짝이었다. **속도와 콤마 break는 함께 조정해야** 균형이 맞는다.
- **Charon 이력 — 취향 사유로 두 번 기각됐다.** 2026-06-13 설계에서 `ko-KR-Chirp3-HD-Charon`으로 갔다가 2026-06-29 `b3d3eeb`에서 Neural2-C로 되돌렸고, 2026-08-10 `3ebf88c`에서 다시 Charon으로 갔다가 **2026-08-11 `aae6588`에서 또 Neural2-C로 되돌렸다**. 두 번 다 사유는 **취향(이전 목소리 복귀)이지 결함이 아니다** — 그 사이 Chirp3-HD 고유 발음 문제(소수점 흘림 `8705cd8`, 한자 괄호 이중발음 `09e7634`, 앰퍼샌드 `cbae665`)를 전부 잡았는데도 판단이 바뀌지 않았다. 발음을 더 고쳐서 Charon을 재제안하는 건 의미가 없다(`options.py` 주석에 같은 취지로 박아둠). PR #5가 세 번째로 Charon을 올렸지만 위 머지 순서 때문에 **실제 화자는 바뀌지 않았다**.
- **업로드 영상의 목소리는 업로드 시점으로 판별한다** — 남성 기본 화자가 `Charon(~06-29) → Neural2-C(06-29~08-10) → Charon(08-10~08-11) → Neural2-C(08-11~)`로 바뀌었다. 즉 **2026-08-10~11 하루 남짓에 올라간 영상만 Charon**이고 나머지 롱폼·쇼츠는 Neural2-C다. 목소리가 바뀐 경계에서 기존 영상과 이어 들으면 차이가 난다.
- **음성 비교 도구** — `scripts/compare_voices.py`가 같은 원고를 여러 화자로 합성해 `~/Downloads/popory_voice_ab/`에 MP3+비교 페이지를 만든다. 실제 영상과 같은 조건(문장별 합성+`SENTENCE_GAP` 무음)으로 들린다. `--list`로 계정의 ko-KR 화자 목록을 조회한다.
- **무료 한도 버킷** — Google Cloud TTS는 Neural2·Chirp3-HD **각각 월 100만 자**가 만료 없이 무료다. 실측 사용량은 월 약 17만 자(SSML 태그 포함, 롱폼 16장면+쇼츠 기준)로 한도의 약 17%. 기본이 Neural2-C로 돌아온 지금은 사용량 대부분이 **Neural2 버킷**에 쌓이고 Chirp3-HD 버킷은 여성 옵션을 쓸 때만 소모된다 — 두 버킷 모두 여유가 크다. 초과 시 Chirp3-HD 단가는 $30/100만 자, Neural2 는 $16/100만 자(2026-09-05 `cloud.google.com/text-to-speech/pricing` 직접 확인 — SKU 가 FEBD…/F977… 로 달라 무료 버킷도 별도다). **구글 AI Plus 멤버십은 API 비용과 무관하다**(앱 혜택 묶음; Gemini API·Cloud 크레딧은 AI Pro/Ultra 전용) — `docs/superpowers/specs/2026-09-05-google-ai-plus-image-tts-free-tier-review.md` 참고. Gemini API 이미지는 무료 티어가 없거나 미확인이라 현행 Cloudflare 유지.
- **아래 전처리는 화자와 무관하게 항상 적용된다** — `synthesize`가 voice에 상관없이 `_prep_text`를 거치므로 Neural2-C에도 숫자→한글·특수문자 정규화·콤마 break가 그대로 걸린다. "Chirp3-HD가 …하더라"는 서술은 **문제를 처음 관찰한 화자**를 가리키는 것이고, 기본이 Neural2-C로 돌아왔다고 해서 되돌릴 규칙이 아니다(여성 옵션은 여전히 Chirp3-HD).
- 입력은 **`ssml` 필드**로 보낸다(`<speak>…</speak>`). 과거 `markup`/`[pause long]`은 제거 — 문장별 합성으로 바뀐 뒤 단일 문장이라 죽은 코드였고, markup 프리뷰 모드가 숫자 정규화를 망가뜨려(아래) `ssml`로 전환. 문장 사이 호흡은 `video.py`의 `SENTENCE_GAP`(0.7초) 무음 갭이 담당.
- **질문 뒤 호흡은 더 길다** — 물음표로 끝난 문장 뒤엔 `SENTENCE_GAP`(0.7초) 대신 `QUESTION_GAP`(1.0초, `POPORY_QUESTION_GAP`) 무음을 둔다(`video._gaps_for`). 질문을 던지고 곧바로 답으로 넘어가면 시청자가 생각할 틈이 없어 톤이 단조롭게 들린다(2026-09). 자막 스팬(`_spans_from_durations`)과 오디오 concat 이 같은 갭 리스트를 쓴다.
- **챕터(상단 헤드라인) 전환은 마침표 인터벌의 2배** — 장면 caption(상단 챕터)이 바뀌는 장면 경계엔 문장 사이 `SENTENCE_GAP`보다 긴 호흡을 둔다. `video.py`의 `CHAPTER_GAP = 2 * SENTENCE_GAP`(1.4초) 무음을 비마지막 장면 오디오 끝에 붙여(`_append_silence`) 한 챕터가 끝났음을 청각적으로 구분한다. 장면 전환 크로스페이드(`XFADE_TD` 0.4초)가 무음 끝을 살짝 먹어 실제 정적은 조금 짧게 들린다. 마지막 장면 뒤엔 넣지 않는다.
- **정수·소수를 붙인 한글로 변환** — 정수(`16`→십육)와 점 1개 소수(`29.2`→이십구점이, 정수부+점+소수부 자리별)를 `_read_number`/`_read_decimal`이 붙인 한글로 치환한다. say-as 태그를 쓰지 않아 뒤 글자와 끊기지 않는다("1차"→"일차"). **소수를 숫자로 두면 안 된다** — Chirp3-HD가 값에 따라(`29.2` 등) 소수점을 흘려 "이십구 이"로 읽는다(2026-07 귀 확인). 붙인 한글은 `29.2`·`41.8` 모두 점을 정확히 읽는다. **시간(3:00)·슬래시 날짜(2024/06)·점 여러 개(2024.06.21·버전 1.2.3)**는 모델에 맡긴다. 퍼센트 기호 `%`는 `_normalize_for_tts`에서 '퍼센트'로 치환(`12.3%`→십이점삼퍼센트), 앰퍼샌드 `&`는 '앤'으로(`S&P`→에스앤피).
- **천 단위 콤마는 통째로 읽기** — `1,700` → `1700`(천칠백)으로 콤마 제거 후 합성.
- **특수문자 정규화**(`_normalize_for_tts`) — Chirp3-HD는 문장부호를 운율로 해석(하이픈=갑작스러운 끊김, 말줄임표=망설임)하므로 어색하다. 구분 대시 `-`·말줄임표 `…`→쉼표, 따옴표·괄호·마크다운 기호 제거, 가운뎃점·콜론→쉼표, 슬래시→공백, 숫자 범위 틸드→'에서' 등. 괄호 안에 한글이 없는 한자·영어 주석은 통째로 지운다(`_PAREN_GLOSS`) — 한자가 앞말과 같은 독음으로 다시 읽혀 이중 발음되는 것 방지(구방심(求放心)→구방심).
- **콤마 호흡** — 콤마를 너무 급히 넘어가는 문제는 SSML `<break time="175ms"/>`를 콤마 뒤에 강제로 넣어 보정한다(`COMMA_BREAK_MS` 기본 175, `POPORY_TTS_COMMA_BREAK_MS`로 튜닝, 0이면 비활성). 단 **콤마 앞이 한 글자면 break를 넣지 않는다**(`_comma_break`) — 고립된 단음절에 무음이 붙으면 받침이 뭉개진다. `<break>`는 실제 무음이라 **`[pause]` 마크업의 "어·으·응" 추임새 부작용이 없다** — 그래서 pause 토큰은 여전히 절대 쓰지 않는다.
- 리터럴 대괄호 `[]`·문장 앞 간투사(음·어…)도 제거.
- **소수는 문장 분할보다 앞서 깨질 수 있다** — TTS 는 문장별로 따로 합성하므로(`video.py` `_split_sentences` → `synthesize`), 분할이 소수점에서 끊기면 `tts.py` 의 소수→한글 변환이 온전한 토큰을 못 받아 무력화된다. 2026-08 에 `6.25`가 `6.` / `25`로 갈려 "육 … 이십오"로, `0.0008`은 `0.` / `0008`(→정수 8)로 갈려 "영 … 팔"로 읽혔다(커밋 `fd07c86`에서 마침표 뒤가 숫자면 끊지 않도록 수정). **tts.py 만 보고 숫자 읽기를 판단하지 말 것** — 그 앞 단계가 텍스트를 어떻게 자르는지까지 확인해야 한다. 같은 이유로 자막도 같은 지점에서 끊긴다.

- **3단 라우터**: 1순위 Cloudflare **flux-2-klein-4b**(무료) → 실패 시 같은 무료 한도의 flux-schnell → 한도 소진·둘 다 실패면 로컬 RealVisXL 폴백. 한도(4006)는 두 모델이 같은 뉴런 풀을 쓰므로 모델을 바꿔도 안 풀린다 — 그날 CF 경로 전체를 접는다.
- **klein-4b 전환은 2026-08-22 실호출 검증 후다**(`workers/api/scripts/smoke_klein4b.sh`). schnell 보다 한 세대 뒤 모델이라 손·얼굴 기형이 덜하다. 뉴런은 1024² 기준 장당 약 104(schnell 58)로 두 배 가까이 쓰지만 하루 24장이면 무료 한도의 25%다. 되돌리려면 `POPORY_CF_IMAGE_MODEL=schnell` 하나면 된다.
- **생성 치수는 포맷마다 다르다**(klein 만 치수를 받는다) — 롱폼 **1536×1024(3:2)**, 쇼츠 **1024×1536(2:3)**, 캐러셀은 정사각이라 미설정(=1024²). 썸네일은 영상 비율을 따른다. `POPORY_CF_IMAGE_SIZE_LANDSCAPE`/`_PORTRAIT`/`_SQUARE`(`"1536x1024"` 형식, 빈 값이면 모델 기본).
- **한 쌍을 전역으로 쓰면 안 된다** — 가로 3:2 원본을 쇼츠(9:16)에 쓰면 확대율은 1.875x 그대로라 **화질 이득이 0인데** 가로로 63%가 잘려 구도가 무너진다. 포맷별로 줘야 양쪽 다 1.250x 가 된다.
- **3:2·2:3 은 화질과 패닝의 교환이다**(실측 `video._pan_headroom`) — 확대율 1.875x→1.250x 로 33% 선명해지는 대신 패닝 여유가 840→200px 로 준다. 30초 장면 팬은 210→200px 로 거의 그대로고 **53초 장면만 371→200px 로 짧아진다.** 16:9 원본은 여유가 0이라 패닝이 아예 사라지므로 쓰지 않는다.
- **스타일 앵커** — 한 작업의 **첫 검수 통과 이미지**를 480px JPEG 로 줄여 이후 장면·썸네일에 `reference_images` 로 물린다(klein 전용). "전 장면 색감·조명 일관"을 프롬프트 문구가 아니라 모델 입력으로 강제하는 수단이다. 참조만 넣으면 모델이 그걸 재현하려 들 수 있어 프롬프트에 `Match the color grading, lighting and overall mood of image 0.` 를 앞에 붙인다. 앵커는 **첫 장면으로 고정**한다 — 매 장면 덮어쓰면 톤이 서서히 흘러간다. 작업마다 새로 만들어 어제 영상 톤이 오늘로 새지 않게 한다. 끄려면 `POPORY_IMAGE_STYLE_ANCHOR=0`.
- **이미지 안에 글자/텍스트 금지.**
- image_prompt는 영어 한 문장. 기본 스타일 키워드 **`photorealistic, cinematic`** (영상 시리즈에 정해진 룩이 따로 있으면 그것을 우선).
- **인물 정책이 2026-08 뒤집혔다 — 얼굴 허용에서 얼굴 회피로.** 이전엔 "얼굴이 보여도 됩니다"였으나 얼굴·눈·손이 기형으로 나오는 빈도가 높아 정책을 바꿨다. `video_prompt.py`가 이제 **뒷모습·실루엣·원경**을 기본으로 유도하고, 그마저 어려우면 사물·풍경·정물로 대체하게 하며 **정면 얼굴·손 클로즈업과 팔짱·턱 괴기 등 팔이 접히거나 교차하는 포즈를 금지**한다. 근본 대책은 검출이 아니라 "애초에 덜 만들기"다.
- 전 장면 **색감·조명·분위기 일관** 유지 → 한 영상처럼.
- 호출 타임아웃 300초. 깨진 imagegen 응답은 검증·재시도(단색 폴백 사각지대 방지).

### 탈락을 만들기 전에 줄이기 — 생성 프롬프트 정책
- **인물 정책은 부탁이 아니라 코드다** — `video_prompt.py` 의 "되도록 넣지 않습니다"는 LLM 이 자주 무시한다(불량 두 장 다 인물이 화면 중앙에 크게 있었다). `apply_people_policy()` 가 생성 직전에 **항상** 접미사를 붙인다: 사람이 없는 프롬프트엔 `NO_PEOPLE_SUFFIX`(모델이 멋대로 인물을 넣는 걸 막음), 사람이 있으면 `SAFE_PEOPLE_SUFFIX`(원경·실루엣·**얕은 심도**·역광·손 숨김). 기형은 그 부위가 크고 선명할 때만 보이므로, 지우는 대신 **실패 표면을 없앤다**.
- **두 접미사를 겹쳐 붙이지 않는다** — "사람을 이렇게 그려라"와 "사람을 빼라"가 한 프롬프트에 같이 들어가면 확산모델이 엉뚱하게 해석한다. 0라운드는 정책, 1라운드 이후는 `harden_prompt` 로 **배타** 적용한다.
- **인물 단어 감지는 반드시 단어 경계로 본다**(`has_person`) — 부분일치로 짜면 `"the "⊃"he "`, `"this "⊃"his "`, `"other "⊃"her "`, `"many"⊃"man"` 이라 **사실상 전량이 사람 있음으로 분류되고 "사람 그리지 마라" 분기가 통째로 죽는다**(2026-08 실제로 이렇게 나갔다). 감지를 놓치는 쪽은 손해가 작다 — 놓치면 `NO_PEOPLE_SUFFIX` 가 붙는데 그건 사람을 안 그리게 하는 지시라 기형이 나올 일이 없다.

### 로컬 imagegen 의 negative_prompt 는 기본값에서 무효다
- `NEGATIVE_DEFAULT`(기형·이상눈·손 방지)가 잘 짜여 있지만 기본 파이프라인이 `guidance=0.0`(RealVisXL + SDXL-Lightning 8스텝)이고, **diffusers 는 `guidance_scale > 1` 에서만 CFG 를 켠다** — 즉 네거티브가 통째로 무시된다. Lightning 의 정석 레시피이긴 하나, 기형 방지 장치가 조용히 꺼져 있다는 뜻이다.
- `POPORY_IMAGEGEN_GUIDANCE` 로 뺐다(기본 0.0 = 기존 동작). **1.5~2.0 이면 Lightning 도 대체로 견디고 네거티브가 살아나는 대신 스텝당 연산이 2배**(장당 ~18초 → ~36초 예상)다. 맥미니 실측으로 정할 문제.
- `/health` 가 `guidance`·`negative_active` 를 노출한다 — 꺼져 있는 걸 밖에서 못 보면 아무도 모른다.

### Cloudflare flux-schnell 은 4스텝 고정이다
- `content_ai_image.ts` 가 `{ prompt }` 만 넘겨 기본 4스텝이다. **저스텝 distilled 에서 가장 먼저 깨지는 게 손과 팔이다.** CF 는 8까지 받지만 뉴런 비용이 스텝에 비례해 **무료 한도(10k/일)와 정면 충돌**하므로 지금은 올릴 수 없다. flux-schnell 은 guidance-distilled 라 negative_prompt 자체가 없다.

### 이미지 이상 검수 (2단 방어) — `image_review.py`, `worker.py` `_safe_image`
1. **생성 전 억제** — 위 프롬프트 정책. 얼굴이 안 나오면 기형도 안 나온다.
2. **생성 후 검수** — `review_image()`가 claude CLI 비전(`--allowed-tools Read`)으로 장당 1회 판정한다. 얼굴 기형·눈 이상(동공 방향·좌우 비대칭·섬뜩한 눈빛)·**결손**(머리 없는 몸통, 손 없는 팔)·**융합/분기**(두 팔이 한 소매로 합쳐짐, 관절 없는 꺾임, 배경에 녹아 붙은 손)·개수 오류·피부톤 불일치·섬뜩한 표정이면 reject.
- **판정은 게슈탈트가 아니라 골격 추적이다.** "이 이미지 기형인가?"만 물으면 모델이 전체 인상으로 답하고, **얼굴이 멀쩡하면 팔이 틀려도 통과한다**. 그래서 SYSTEM_PROMPT가 인물마다 `어깨 → 상완 → 팔꿈치 → 전완 → 손목 → 손`을 적게 강제하고, 주인공만이 아니라 **화면 안 모든 인물**을 보게 한다. 서술을 강제해야 "팔은 2개인데 손이 1개"가 드러난다.
- **실제로 샌 두 장(2026-08)** — ① 병원 복도: 오른쪽 인물의 머리가 통째로 없고(뒤쪽 벽 뷰박스가 그 자리를 차지) 손만 주황색. ② 책상 앞 여학생: 두 팔이 한 소매로 융합, 상완·팔꿈치 부재, 시계 낀 팔에 손 없음. **둘 다 얼굴은 정상**이었고 둘 다 **팔짱·턱 괴기** 포즈였다 — 팔이 몸 앞에서 접히거나 교차하고 손이 몸에 닿는 구도가 확산모델이 팔 연결을 가장 많이 잃는 지점이다. `video_prompt.py`가 이 포즈를 금지한다.
- **결손과 프레임 밖 크롭을 구분하는 문구가 필수다** — 없으면 판정자가 안전하게 ok로 흘린다. 기준: 몸통이 화면 안에 온전한데 이어질 부위가 비어 있으면 결손. 가린 물체가 인물보다 **뒤·옆**에 있으면 가림이 아니라 결손.
- **"뒷모습·실루엣은 ok" 조항이 머리 없는 몸을 삼킨다** — 머리가 없어서 얼굴이 안 보이는 것을 "얼굴 안 보이는 인물"로 오독한다. 예외를 명시해 뒀다.
- **"애매하면 ok"의 예외는 결손·융합** — 사지를 어깨에서 손까지 못 따라가면 애매해도 reject. 그 외에는 과잉 차단이 단색 배경보다 나쁘다는 원칙을 유지한다.
- **책·간판 글자 뭉개짐은 reject 대상이 아니다.** 시청자가 읽지 않는다. 기형과 다른 유형이라 섞으면 탈락률만 올라간다.
- **탈락하면 프롬프트를 단계적으로 후퇴시켜 재생성한다**(`harden_prompt`): 1라운드 = 뒷모습·실루엣 + 팔 벌린 자세 강제(팔짱·턱 괴기 금지), 2라운드 = 인물 완전 제거. 같은 프롬프트로 다시 뽑으면 같은 기형이 재현되기 때문이다. 라운드 수는 `POPORY_IMAGE_REVIEW_ROUNDS`(기본 2).
- **끝까지 탈락해도 마지막 이미지를 쓴다.** None을 돌려주면 배경이 단색이 되고 `_finalize_video`가 영상을 failed/review로 떨어뜨린다 — 기형 의심 한 장이 그보다 낫다. 이때 `image_review_exhausted` 로그가 남는다.
- **fail-open이 원칙** — CLI 오류·타임아웃·파싱 실패는 전부 통과 처리한다. 검수는 품질 장치이지 생성 차단 장치가 아니며, 검수 때문에 데일리 배치가 멈추면 안 된다. **단 통과 사유에 `검수불가:` 접두사를 남겨** 진짜 통과와 구분하고(`is_unavailable`), 워커가 `image_review_error`로 로그한다 — 구분이 없으면 claude 인증이 만료된 날 전량이 무검수로 통과하는데 아무도 모른다.
- **탈락 0건을 곧바로 "다 멀쩡함"으로 읽지 말 것.** 검수기가 죽어도 0건이 나온다. `image_review_error` 건수를 먼저 확인하고, 그다음 표본이 대표성 있는지(잡 한두 개에 몰리지 않았는지) 본다.
- **적용 범위**: 장면 배경, 쇼츠 배경, 캐러셀 슬라이드, **썸네일**까지 전부 `_safe_image`를 거치므로 자동 포함된다.
- **비용·지연**: 장당 claude CLI 1회(타임아웃 90초·2시도). 하루 24장이면 최소 24회 추가 호출이다. 끄려면 `POPORY_IMAGE_REVIEW=0`. 판정 로그는 `image_rejected`(사유·라운드·프롬프트 포함).
- **소급 스캔** — `scripts/scan_images.py`가 **이미 만들어진 이미지**를 같은 기준으로 일괄 검수한다. `--limit`은 잡 디렉터리 전체에 라운드로빈으로 펴서 뽑는다(`_spread`) — 앞에서 자르면 정렬상 앞선 잡 한두 개만 보게 돼 대표성이 없다(2026-08 30장이 잡 2개에 몰려 탈락 0건이 나온 사례). 인자 없이 돌리면 `/tmp/video_*/`의 장면 배경 PNG를 스캔하고(워커가 작업 디렉터리를 지우지 않아 남아 있다), `--video`로 완성 MP4에서 프레임을 뽑아 검수할 수도 있다. 결과는 `~/Downloads/popory_image_scan/<시각>/`에 `index.html`·`results.json`·`images/`(스캔한 **전량** 사본)로 나오며, 장당 기록해서 중간에 끊겨도 남는다. **리포트는 통과분까지 싣는다** — 탈락분만 실으면 0건일 때 볼 게 없어, 판정이 느슨해 놓친 건을 사람이 확인할 수 없다. 탈락·검수불가를 앞에 모으고 이미지를 클릭하면 원본이 열린다. **번호는 스캔 순서로 고정**돼 있어(정렬이 바뀌어도 유지) `--list <results.json>`이 뽑는 텍스트 체크리스트와 화면이 대응한다 — 육안 검토 후 판정이 틀린 번호를 지목하면 된다.
- **판정만 보면 진단이 안 된다** — `--explain <이미지>`가 그 한 장의 판정 근거(골격 추적 서술)를 원문 그대로 찍는다. 추적이 결함을 짚었는데 ok 면 **판정 문턱** 문제고, 추적이 "정상"이라고 썼으면 **모델이 못 본 것**이라 프롬프트로는 안 고쳐진다(모델·해상도 문제). 통과 0건이 계속될 때 기준부터 조이지 말고 이걸 먼저 볼 것.
- **골격 추적을 시켰더니 거짓 확신이 나왔다(2026-08)** — 상완이 안 보이는 팔을 "어깨→상완→팔꿈치→전완→손목→손까지 끊김 없이 추적되며 손가락도 확인됨"이라고 서술하고 ok. 서술을 강제하면 "못 봤다"가 "확인했고 정상이다"로 바뀔 뿐이라 **로그에 거짓 확신만 쌓인다**. 통과가 계속되면 프롬프트를 더 조이지 말고 해상도·모델을 의심할 것 — `--tile 2`(겹쳐 자른 조각별 판정)와 `--model`로 가른다. 통째로는 못 잡던 결함이 조각에서 잡히면 원인은 기준이 아니라 **claude Read 의 이미지 축소**다.
- **0건이 나오면 표본부터 의심한다** — `--limit`은 매번 `/tmp/video_*`를 다시 뽑으므로 잡이 쌓이면 표본이 통째로 바뀐다. 아는 불량 이미지가 그 표본에 들었는지 확인하지 않은 0건은 기준 실패의 증거가 아니다.

## 영상 조립 (기술) — `video.py`
- 켄번스 줌(2x 슈퍼샘플로 떨림 제거), 장면 전환 크로스페이드(xfade/acrossfade).
- **체감을 정하는 건 총 줌 폭이 아니라 초당 속도다** — 폭을 장면 전체에 균등 분산하면 장면이 길수록 느려진다. 롱폼은 장면이 32~53초라 초당 0.19~0.44%까지 떨어져 **정지 화면처럼 보였다**(2026-08-08 확인). 쇼츠(장면 7초, 초당 1.71%)에서만 무빙이 보였던 이유가 이것이다. **쇼츠에서 잘 보인다고 롱폼도 괜찮다고 판단하지 말 것.**
- **한 장면을 8초 샷으로 쪼개 샷마다 구도를 바꾼다(2026-09)** — 롱폼 장면은 30~50초라 켄번스만으로는 "그림 한 장이 서 있는" 느낌이었다. `SHOT_SECONDS`(8, `POPORY_SHOT_SECONDS`) 단위로 `_shot_count` 만큼 나눠 zoompan 식을 `mod(on, seg)`·`floor(on/seg)` 로 구간화한다. 샷마다 줌 폭은 샷 길이 기준(8초 → 하한 0.06, 초당 1.5% = 쇼츠 체감)이고 홀수 샷은 방향과 가로 기준점을 뒤집는다. 짝수 샷이 1.0 에서 끝나고 홀수 샷이 1+amp 에서 시작해 **경계에서 확대율이 점프하는 게 컷**이다(ffmpeg 실측: 경계 프레임 차 29 vs 샷 안 0.9초 드리프트 9). 이미지를 더 만들지 않으므로 생성 비용 0. 두 샷이 안 나오는 장면(쇼츠 7초)은 예전 식 그대로.
- **왕복(삼각파) 줌** — `ZOOM_RATE_PER_SEC`(0.7%/s)를 고정하고 폭은 길이에서 역산한다(`_zoom_amplitude` = 속도 × 길이/2). 절반까지 갔다 되돌아오므로 **최대 확대율을 묶은 채 속도만 올릴 수 있다.** 한 방향으로만 밀면 인지 가능한 속도에서 총 확대율이 32%까지 커져 1024px 원본이 무너진다. 폭 하한 0.06은 쇼츠 체감(초당 1.71%)을 유지하고, 상한 0.18은 과확대를 막는다.
- **줌 무빙은 장면마다 다르다** — `_MOTIONS` 6종(확대로 시작 여부 × 가로 기준점 0.35·0.50·0.65)을 장면 인덱스로 순회하고, 시작점은 job_id(`zlib.crc32`)로 정해 같은 작업은 항상 같은 결과가 나온다. 인접 항목은 방향이 서로 달라(순환 지점 포함) 같은 무빙이 연달아 붙지 않는다.
- **배경 패닝은 크롭을 덜 하는 것이지 확대를 더 하는 게 아니다** — 원본을 프레임에 커버하면 그만큼 여유가 남는다(`_pan_headroom` — 정사각 1024²는 840px, 기본값인 3:2 1536×1024는 200px). 그만큼 캔버스를 키워 그 안에서 프레임 창을 움직이므로 **확대율이 늘지 않아 화질 손실이 0**이다. 여유가 없는 16:9 원본은 패닝을 걸지 않는다. 패닝은 왕복하지 않고 편도다(확대율을 안 건드려 되돌아올 이유가 없고 같은 여유로 두 배 멀리 간다). 속도 `PAN_RATE_PX_PER_SEC`(7px/s)는 줌 0.7%/s와 체감을 맞춘 값 — 1080px의 0.7%가 초당 7.6px다.
- **필터 순서를 바꾸지 말 것** — `scale`(긴 캔버스) → `zoompan`(s는 **입력과 같은 크기**) → `crop`(프레임 창 이동) → `scale`(출력). zoompan은 입력 종횡비 그대로 크롭하므로 긴 캔버스를 먹이고 s만 16:9로 주면 **화면이 눌린다**. 그리고 **crop을 zoompan 앞에 두면 패닝이 얼어붙는다** — zoompan이 첫 입력 프레임을 d프레임 동안 붙들기 때문(2026-08 ffmpeg 실측, 첫·끝 프레임이 완전히 동일하게 나옴).
- **스크림은 화면 고정 오버레이**(`_render_scrim_png`) — 배경에 구우면 패닝 때 배경과 함께 밀려 자막 뒤가 밝아진다. 오버레이 순서는 스크림 → 헤드라인 → 자막.
- **비용 감각** — 렌더 비용은 수퍼샘플 캔버스 **면적에 정비례**한다. 같은 캔버스 안에서 줌 방향·기준점·폭을 바꾸는 건 공짜지만, 패닝 여유만큼 캔버스가 커지면 딱 그 비율로 느려진다(44.6초 장면 실측 82.4초 → 104.0초, 1.26배 = 캔버스 면적비 1.29와 일치). 용량은 +17%로 maxrate 1200k 상한에 닿지 않아 **재조정 불필요**(11.8분 영상 54MB → 약 63MB, 100MB 한도 안).
- **원본 해상도는 생성기마다 다르다** — 로컬 RealVisXL은 **768×768**, CF schnell 은 1024×1024, CF klein-4b 는 포맷별 지정값(롱폼 1536×1024, 쇼츠 1024×1536, 캐러셀 1024²)이다. **폴백으로 내려가면 해상도가 같이 떨어져** 한 영상 안에서도 장면마다 다를 수 있다. 768이면 1920 가로 기준 2.5배 확대 상태라 줌 폭을 키울수록 화질이 직접 깎인다. 1024로 가정하지 말 것.
- 라이선스-프리 BGM 패드 + 음량 정규화(loudnorm) 마스터 패스. **BGM 은 기본 꺼져 있다**(`POPORY_BGM_ENABLED=0`, 2026-07-03 요청). 켜면 `_bgm_for` 가 `assets/bgm/*.mp3` 를 파일명으로 두 버킷(단조 `min`/`_am` = tense, 나머지 = warm)으로 나눠 **전반 55% 는 tense, 후반은 warm 으로 한 번 전환하는 베드**(`_build_bgm_bed`, acrossfade 4초)를 만든다. 한쪽 버킷이 비면 예전처럼 한 곡. `POPORY_BGM_SWITCH_RATIO` 로 전환 지점 조절.
- 자막은 문장 단위 타이밍, 헤드라인 단일 자막.
- **쇼츠 자막은 YouTube UI 를 피해 올린다** — 재생기가 프레임 하단 약 20%(1920 기준 384px)를 제목·채널명·설명·CTA 로 덮는다. 예전 값(하단에서 305px)은 그 한복판이라 번인 자막과 YouTube 제목이 겹쳐 **둘 다 안 읽혔다**(2026-08-22 업로드분에서 확인, UI 안으로 139px 침범). 지금은 `PORTRAIT_UI_SAFE_BOTTOM`(384) 위로 여백 56px 을 두고 배치한다 — 자막 하단이 1480px, 안전선이 1536px 이다. 가로형은 재생 중 UI 가 숨으므로 175 그대로다.
- **번인 자막은 항상 한 줄** — `_wrap_chunks`가 어절 경계에서 한 줄 길이(가로 30자·세로 18자)로 쪼개고 `_chunk_spans`가 순차 표시한다. 예전엔 문장을 통째로 렌더해 **86%가 2~4줄**이었다(2026-08-08 실측 98개 중 1줄 14%·2줄 57%·3줄 26%·4줄 3%).
- **조각 타이밍은 발화 평문 길이로 나눈다** — TTS는 문장 단위로 합성하므로 문장 *안*은 실측이 불가능해 길이 비례로 추정할 수밖에 없다. 이때 원문이 아니라 `tts.spoken_text`(특수문자 정규화 + 숫자→한글) 길이를 써야 한다. `1,700`은 5글자지만 '천칠백' 3음절로 읽혀 원문 기준이면 그 조각이 과대평가돼 자막이 밀린다. 마지막 조각은 문장 뒤 무음까지 유지해 깜빡임을 막는다.
- **cue(=SRT)는 절대 쪼개지 않는다** — cue는 `_store_subtitles`에서 `translate_lines`로 EN/ZH/JA 번역돼 SRT 4종으로 올라간다. 문장 조각을 번역기에 넘기면 주어·술어가 잘려 번역이 무너진다. **화면 표시용 분할과 cue를 반드시 분리할 것.**
- **자막을 문장 중간에서 쪼개 TTS로 합성하지 말 것** — 조각별 합성은 타이밍은 정확해지지만 문장 중간에 종결 억양과 무음이 생긴다(소수점 분할 사고와 같은 계열).
- 챕터 헤드라인은 68px Bold(가로)·58px Bold(세로), `FONT_INDEX_BOLD`=6(AppleSDGothicNeo.ttc의 Bold face). **검정 외곽선 필수** — 헤드라인은 하단 스크림 밖(좌상단)이라 배경이 밝으면 굵게 키워도 흰 글씨가 그대로 묻힌다(밝은 벽 장면에서 확인).
- **헤드라인 왼쪽에 포포리 책방 로고** — `assets/logo.png`를 `_logo_circle`이 원형으로 마스킹해 얹고, 제목은 로고 오른쪽에 세로 중앙 맞춤으로 그린다. 원본이 **알파 없는 검정 배경 108×108**이라 그대로 얹으면 밝은 장면에서 검은 사각형이 드러나고, 96px보다 크게 쓰면 뭉개진다. 로고 파일이 없거나 깨지면 글자만 그리고 넘어간다(영상 전체를 막지 않는다).
- **렌더 해상도 그대로 내보낸다** — 쇼츠는 1080×1920 으로 렌더한 뒤 **540×960 으로 줄여** 내보냈는데(`PORTRAIT_OUT_W/H`), 유튜브가 폰 화면으로 되키우면서 번인 헤드라인·자막이 눈에 띄게 흐려졌다(2026-08-23 확인 — 같은 화면에서 YouTube 가 그리는 하단 제목은 선명한데 구워 넣은 글자만 뭉갰다). 글리프 가장자리는 고주파라 축소→확대에 가장 먼저 무너진다. **축소는 얻는 것도 없었다** — 용량은 maxrate 가 잡고, 60초 쇼츠는 상한을 다 써도 100MB 한도의 한참 아래다. 지금은 마스터 단계가 항상 `-c:v copy` 라 3세대 인코딩도 사라졌다.
- **인코딩 품질은 포맷별로 갈린다**(`_x264_q`) — 롱폼은 10분까지 가므로 100MB 안에 들어오려면 상한이 빡빡하고(`-crf 28 -maxrate 1200k`), 쇼츠는 60초라 같은 한도 안에서 훨씬 후하게 준다(`-crf 23 -maxrate 6000k` ≈ 37MB). **쇼츠에 롱폼 상한을 쓰면 안 된다** — 1080×1920@30 에 1.2Mbps 면 줌·패닝 모션이 비트를 다 가져가고 정지한 글자 가장자리가 먼저 무너진다. 가로형이 기본 CRF면 긴 영상이 100MB를 넘어 **포털 업로드가 413(Cloudflare 엣지 본문 한도)** 로 실패한다(14분 124MB→69MB). `POPORY_VIDEO_CRF`·`POPORY_VIDEO_MAXRATE`(롱폼), `POPORY_SHORTS_CRF`·`POPORY_SHORTS_MAXRATE`(쇼츠)로 튜닝하며, `-bufsize` 는 maxrate 의 2배로 파생되므로 따로 맞출 필요 없다.

## LLM 모델 — 포털 어드민 `/admin/llm-models`
- **기능별로 고른다** — 블로그·롱폼 대본·쇼츠 대본·캐러셀·커뮤니티 글·댓글 답글·자막 번역·주간 추천·이미지 검수 9개. 카탈로그는 `workers/api/src/lib/llm_catalog.ts` 한 곳에 있고 API 가 어드민·워커 양쪽에 내려준다(목록이 갈라지면 어드민에서 고른 값이 워커에서 안 먹는다).
- **기본값은 `claude-sonnet-5`**(2026-08-23 에 `claude-sonnet-4-6` 에서 올렸다), `POPORY_CLAUDE_MODEL` 로 덮는다. 기본값을 바꾸면 그 값으로 저장돼 있던 기능은 어드민에서 오버라이드로 보인다 — 기본값 선택 시 행을 지우는 설계라 다음 저장에서 정리된다. 어드민에서 기본값을 고르면 행을 지운다 — 남겨 두면 나중에 기본값을 바꿔도 옛 값에 묶인다.
- **워커는 폴 사이클마다 `/api/content/llm-models` 를 읽는다**(TTL 60초, `POPORY_LLM_MODELS_TTL`). 저장하면 **다음 작업부터** 먹고 워커 재시작이 필요 없다. 조회 실패는 삼키고 직전 값(없으면 기본값)으로 계속 간다 — 설정을 못 읽었다고 배치를 멈추지 않는다.
- **호출은 맥미니 claude CLI 를 거친다** — Claude 플랜에 없는 모델을 고르면 그 기능이 `claude CLI exit 1` 로 실패한다. 카탈로그에 있다고 다 되는 게 아니다.
- `POPORY_IMAGE_REVIEW_MODEL` 은 어드민 설정보다 우선한다(현장에서 급히 되돌릴 통로).
- 모델 해석은 `generate.model_for(기능키)` 하나로 모은다. 대본·번역·검수 호출부가 서로 다른 모듈이라 포털 클라이언트를 거기까지 실어 나르면 시그니처만 번진다.

## 신뢰성 / 작업 상태
- claude CLI 일시 실패(parse 실패 등)에 재시도 내성.
- 누락 이미지 비율로 status 결정 — 대부분 실패면 `failed`(재생성 필요), 일부면 `review`+경고.
- 작업 상태 흐름 `queued → running → review/failed`. claim은 `queued`만 집어가고 **`running`에 고아로 남은 작업을 회수하는 lease/timeout이 없다** — worker가 생성 도중 재시작되면 그 작업이 "생성 중"에 영구히 묶인다(직접 `running→queued` 복구 필요). 재발 방지는 미구현.

## 흔한 실수
- 쇼츠에 구독·좋아요 CTA를 넣거나, 롱폼 **본문** 장면에 CTA 를 넣음(롱폼은 마지막 엔딩 CTA 장면에만).
- 롱폼 첫 장면을 서정적 배경 묘사로 시작함(프리후크 규칙 위반 — 첫 문장은 결론·대비).
- description 마지막 줄 브랜딩을 빠뜨리거나 문구를 바꿈 (정확히 그대로 넣어야 함).
- 유튜브 장면 narration을 너무 짧게 써서 영상이 설정보다 짧아짐.
- 이미지 프롬프트에 텍스트를 넣거나 얼굴 클로즈업·기형 인체를 유발.
- 코드 수정 후 **worker 재시작을 잊어** 변경이 반영 안 됨 (worker는 장기 상주 프로세스라 모듈을 메모리에 들고 있음).
