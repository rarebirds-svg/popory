# 포포리 책방 콘텐츠 생성 피드백

## 개요

popory `services/content`가 한 주제로 4개 채널(블로그·유튜브 동영상·쇼츠·인스타 캐러셀) 콘텐츠를 claude CLI + 로컬 imagegen + TTS로 생성한다. 채널 브랜드는 **포포리 책방 — 한 권의 책에서 길어올린 인생의 지혜**. 이 문서는 그동안 생성 결과를 보며 주고받은 피드백을 모은 단일 레퍼런스다. 규칙은 `prompt.py`(블로그)·`video_prompt.py`(유튜브·쇼츠)·`instagram_image_prompt.py`(캐러셀)·`tts.py`(내레이션 음성)·`video.py`(조립)에 반영돼 있다.

## 언제 사용

- 콘텐츠 생성 프롬프트(`*_prompt.py`)나 TTS·영상 조립 코드를 수정할 때.
- 생성물 검토 중 "왜 이렇게 나오지/이건 안 됐었는데" 판단이 필요할 때.
- 새 채널·옵션을 추가할 때 기존 합의 사항을 깨지 않으려 할 때.

## 공통 원칙 (모든 채널)

- **사실 우선.** WebSearch·WebFetch로 신뢰 자료 수집, 사용자 참고 링크 반영, **확인된 사실만**. 근거 부족 시 추측 금지.
- 자연스러운 한국어 구어체. **문장은 마침표로 끝낸다** (콜론 종결 금지). 단 영상 내레이션(유튜브·쇼츠)은 **물음표 종결도 허용** — 아래 어미 다양화 규칙 참조.
- **간투사·추임새 금지** — '음·어·아·그' 같은 의미 없는 말은 대본·내레이션에 쓰지 않는다.
- 스타일 프로필 샘플이 있으면 그 어조·문장 길이·표현을 따른다.
- 출력은 항상 지정된 두 태그(예: `<scenes_json>`/`<video_meta>`)를 정확히 포함하고, 태그 안엔 ``` 코드블록 표시를 넣지 않는다.
- **외국 저자명은 국내 출판 표기를 쓴다** — 국립국어원 외래어표기법이 아니라 **책 표지에 박힌 표기**다. 독자가 검색창에 치는 게 그쪽이고, 제목의 인명이 틀리면 검색 유입이 통째로 날아간다. 2026-08-23 발행분에서 Bodo Schäfer 가 `보도 새퍼`(정: `보도 섀퍼`)로 나가 제목·대본·태그가 함께 오염됐다. 안전망으로 `names.py` 의 교정표가 claude 출력 길목(`run_claude_cli`)에서 한 번, 추천→주제 등록 직전(`auto_create`)에서 한 번 걸린다 — 후자는 교정 이전에 포털에 쌓인 행을 잡기 위한 것이다. **교정표에 새 항목을 추측으로 넣지 말 것** — 서점 상세페이지로 확인한 표기만 넣는다. 출판사마다 갈리는 이름(말콤/맬컴 글래드웰)은 어느 쪽도 오타가 아니므로 넣지 않는다.

## CTA·브랜딩 규칙 (채널별로 상반되니 주의)

| 채널 | 구독/좋아요/팔로우 유도 | 마무리 |
|------|------------------------|--------|
| 유튜브·쇼츠 | 내레이션·마무리엔 **절대 금지**. **description엔 구독 CTA 허용**(2026-07 구독 성장 위해 완화) | description은 요약만 생성 → `parse_video`가 구독 링크(정확한 채널 ID)+브랜딩을 **결정적 append** |
| 블로그 | 해당 없음 | 출처 표기·SEO 우선 |
| 인스타 캐러셀 | **팔로우 유도 OK** (첫·마지막 슬라이드) | caption 해시태그 포함 |

영상 description은 내용 2~3문장(쇼츠는 1~2문장) 요약만 생성한다. 구독 링크·브랜딩 줄은 프롬프트가 아니라 `video_contract.parse_video`가 `append_description_cta`로 붙인다(LLM이 URL을 지어내 깨지는 것 방지). 구독 URL은 `video_prompt.CHANNEL_SUB_URL`(`?sub_confirmation=1`).

**제목(title)은 훅을 앞, 책 제목을 뒤에** 둔다(`{훅} — {책제목}`, 앞 15자 훅). 예 `140억을 만든 한 문장 — 피터 린치`. (2026-07 CTR 개선. 이전엔 형식 규칙 없어 책 제목이 앞서곤 했다.)

**데일리 주제 큐레이션은 투자·돈·경제 ~60% 비중**(`recommend_weekly.py`). 채널에서 투자 주제 조회수가 1위라 가중.

**업로드 영상은 주제별 재생목록 자동 분류**(`youtube_playlist.py`). 제목·태그 키워드로 4버킷(투자·경제 / 자기계발·습관 / 인문·철학 / 시·에세이, 미분류는 기본) → find-or-create → 추가. `run_upload_once`에서 호출, `POPORY_YOUTUBE_PLAYLISTS=0`으로 끔. 실패해도 업로드 done 유지.

## 채널별 규칙

### 블로그 (네이버) — `prompt.py`
- 시맨틱 **HTML 조각**만 출력 (`<h2><h3><p><ul><blockquote><table>`). `<html>·<body>·<script>·<style>` 래퍼 금지.
- 이미지 2~4장 임베드. `<figure><img><figcaption>출처: 매체 (링크)</figcaption>` — **출처 표기 필수**, 출처 모르면 넣지 않음.
- 관련 YouTube 1~2개 임베드 (`youtube-nocookie`, **실제 존재 영상만**).
- SEO: 핵심 키워드를 `<h2>`·첫 문단에 자연 배치. 원문 길게 복붙 금지(패러프레이즈). 사실·수치·인용·이미지·영상 출처 표기.

### 유튜브 동영상 — `video_prompt.py`
- 장면(scene) 약 N개(**기본 8장면**). 각 장면 = caption(16자 이내 핵심 헤드라인, 공백 포함 기준) + narration + image_prompt(영어, 글자 없음).
- **각 장면 narration은 소리 내어 ~35초(보통 5~7문장)** 로 충분히 풀어 쓴다. 짧으면 영상이 설정 길이보다 짧아짐 → 사례·설명·맥락으로 채운다.
- 도입(후킹) → 본문 → 마무리(여운).
- **어미 다양화 (2026-08 톤 단조로움 개선)** — TTS가 문장별로 독립 합성되므로(`video.py` `_split_sentences`→`synthesize`) 어미가 같으면 모든 문장이 동일한 종결 억양(하강조)으로 끝나 기계적으로 들린다. 대응: ① 합쇼체(~습니다) 기본에 해요체 종결(~죠·~거든요·~인데요·~예요) 혼용, ② '-ㅂ니다/-습니다' **3문장 연속 금지**, ③ 장면당 1문장 정도 수사 의문문(**물음표 종결** — 물음표가 있어야 TTS가 상승조를 붙인다). 쇼츠에도 축약 적용. 문장 분할 regex(`[.?!]`)·자막 파이프라인은 물음표를 이미 처리한다. 이걸로 부족하면 다음 단계는 장면 단위 통합 합성(+v1beta1 `<mark>` 타임포인트)이나 Chirp3-HD 남성 화자 A/B(Charon 제외 — 두 번 기각 이력).

### 쇼츠 (세로 9:16) — `video_prompt.py` `_shorts_rules`
- 60초 이내. 장면 **기본 5개**. caption 10자 이내, narration 1~2문장(짧고 강렬).
- 첫 장면 강렬한 후킹, 마지막 장면 핵심 메시지.
- 자막 줄바꿈 너비 좁게 + 하단 여백 확보(세로 화면).

### 인스타 캐러셀 — `instagram_image_prompt.py`
- 슬라이드 N장(**기본 7장**). 첫=후킹 제목, 중간=핵심 1개씩, 마지막=요약+팔로우 유도.
- 각 슬라이드 title(10자 이내) + body(2~3줄) + image_prompt(영어, **정사각형**, 글자 없음).
- 전체 caption(해시태그 포함, 500자 이내) 작성.

## TTS (영상 내레이션) — `tts.py`
- 기본 음성 **`ko-KR-Neural2-C`(남성)** — `options.py`의 `VOICE["male"]`, `DEFAULTS`가 `voice: "male"`. 선택지 `female-calm`=`ko-KR-Chirp3-HD-Aoede`, `female-bright`=`ko-KR-Chirp3-HD-Leda`. pitch는 아예 보내지 않는다(모델 기본값).
- **말속도 `SPEAKING_RATE` 기본 1.06** (`POPORY_TTS_SPEAKING_RATE`로 튜닝). ⚠️ **근거와 현재 값이 어긋나 있다** — 1.06은 Chirp3-HD 기준 귀 튜닝값이고(`294f614` 2026-06-26, 콤마 break 350→175ms와 한 세트), 1.0이 Neural2 기준값이다(`f8e2898` 06-29, Charon→Neural2-C 되돌림과 짝). 2026-08 Charon 복귀 때 1.06으로 올렸는데 `aae6588`(08-11)에서 음성만 Neural2-C로 되돌리고 속도는 1.06에 남았다. **귀로 확인해 1.0으로 내릴지 정할 것.** 속도와 콤마 break는 함께 조정해야 균형이 맞는다.
- **Charon은 두 번 기각됐다** — 2026-06-13 설계에서 Charon으로 갔다가 06-29 `b3d3eeb`에서 Neural2-C로 되돌렸고, 2026-08 `3ebf88c`에서 다시 시도했으나 `aae6588`(08-11)에서 또 되돌렸다. 두 번 다 사유는 **취향(이전 목소리 복귀)이지 결함이 아니다**. 세 번째 시도를 제안하기 전에 이 이력을 먼저 말할 것. `tts.py`의 정규화·break 튜닝은 Chirp3-HD를 겨냥해 만든 것이라 기본 음성(Neural2-C)과 계보가 다르지만, 두 모델 모두에 적용해도 해롭지 않다.
- **음성 비교 도구** — `scripts/compare_voices.py`가 같은 원고를 여러 화자로 합성해 `~/Downloads/popory_voice_ab/`에 MP3+비교 페이지를 만든다. 실제 영상과 같은 조건(문장별 합성+`SENTENCE_GAP` 무음)으로 들린다. `--list`로 계정의 ko-KR 화자 목록을 조회한다.
- **무료 한도 버킷** — Google Cloud TTS는 Neural2·Chirp3-HD **각각 월 100만 자**가 만료 없이 무료다. 실측 사용량은 월 약 17만 자(SSML 태그 포함, 롱폼 16장면+쇼츠 기준)로 한도의 약 17%. Charon 전환으로 세 음성이 모두 Chirp3-HD 버킷 하나를 쓰지만 여전히 여유가 크다. 초과 시 단가는 Chirp3-HD $30/100만 자.
- 입력은 **`ssml` 필드**로 보낸다(`<speak>…</speak>`). 과거 `markup`/`[pause long]`은 제거 — 문장별 합성으로 바뀐 뒤 단일 문장이라 죽은 코드였고, markup 프리뷰 모드가 숫자 정규화를 망가뜨려(아래) `ssml`로 전환. 문장 사이 호흡은 `video.py`의 `SENTENCE_GAP`(0.7초) 무음 갭이 담당.
- **챕터(상단 헤드라인) 전환은 마침표 인터벌의 2배** — 장면 caption(상단 챕터)이 바뀌는 장면 경계엔 문장 사이 `SENTENCE_GAP`보다 긴 호흡을 둔다. `video.py`의 `CHAPTER_GAP = 2 * SENTENCE_GAP`(1.4초) 무음을 비마지막 장면 오디오 끝에 붙여(`_append_silence`) 한 챕터가 끝났음을 청각적으로 구분한다. 장면 전환 크로스페이드(`XFADE_TD` 0.4초)가 무음 끝을 살짝 먹어 실제 정적은 조금 짧게 들린다. 마지막 장면 뒤엔 넣지 않는다.
- **정수·소수를 붙인 한글로 변환** — 정수(`16`→십육)와 점 1개 소수(`29.2`→이십구점이, 정수부+점+소수부 자리별)를 `_read_number`/`_read_decimal`이 붙인 한글로 치환한다. say-as 태그를 쓰지 않아 뒤 글자와 끊기지 않는다("1차"→"일차"). **소수를 숫자로 두면 안 된다** — Chirp3-HD가 값에 따라(`29.2` 등) 소수점을 흘려 "이십구 이"로 읽는다(2026-07 귀 확인). 붙인 한글은 `29.2`·`41.8` 모두 점을 정확히 읽는다. **시간(3:00)·슬래시 날짜(2024/06)·점 여러 개(2024.06.21·버전 1.2.3)**는 모델에 맡긴다. 퍼센트 기호 `%`는 `_normalize_for_tts`에서 '퍼센트'로 치환(`12.3%`→십이점삼퍼센트), 앰퍼샌드 `&`는 '앤'으로(`S&P`→에스앤피).
- **천 단위 콤마는 통째로 읽기** — `1,700` → `1700`(천칠백)으로 콤마 제거 후 합성.
- **특수문자 정규화**(`_normalize_for_tts`) — Chirp3-HD는 문장부호를 운율로 해석(하이픈=갑작스러운 끊김, 말줄임표=망설임)하므로 어색하다. 구분 대시 `-`·말줄임표 `…`→쉼표, 따옴표·괄호·마크다운 기호 제거, 가운뎃점·콜론→쉼표, 슬래시→공백, 숫자 범위 틸드→'에서' 등. 괄호 안에 한글이 없는 한자·영어 주석은 통째로 지운다(`_PAREN_GLOSS`) — 한자가 앞말과 같은 독음으로 다시 읽혀 이중 발음되는 것 방지(구방심(求放心)→구방심).
- **콤마 호흡** — 콤마를 너무 급히 넘어가는 문제는 SSML `<break time="175ms"/>`를 콤마 뒤에 강제로 넣어 보정한다(`COMMA_BREAK_MS` 기본 175, `POPORY_TTS_COMMA_BREAK_MS`로 튜닝, 0이면 비활성). 단 **콤마 앞이 한 글자면 break를 넣지 않는다**(`_comma_break`) — 고립된 단음절에 무음이 붙으면 받침이 뭉개진다. `<break>`는 실제 무음이라 **`[pause]` 마크업의 "어·으·응" 추임새 부작용이 없다** — 그래서 pause 토큰은 여전히 절대 쓰지 않는다.
- 리터럴 대괄호 `[]`·문장 앞 간투사(음·어…)도 제거.
- **소수는 문장 분할보다 앞서 깨질 수 있다** — TTS 는 문장별로 따로 합성하므로(`video.py` `_split_sentences` → `synthesize`), 분할이 소수점에서 끊기면 `tts.py` 의 소수→한글 변환이 온전한 토큰을 못 받아 무력화된다. 2026-08 에 `6.25`가 `6.` / `25`로 갈려 "육 … 이십오"로, `0.0008`은 `0.` / `0008`(→정수 8)로 갈려 "영 … 팔"로 읽혔다(커밋 `fd07c86`에서 마침표 뒤가 숫자면 끊지 않도록 수정). **tts.py 만 보고 숫자 읽기를 판단하지 말 것** — 그 앞 단계가 텍스트를 어떻게 자르는지까지 확인해야 한다. 같은 이유로 자막도 같은 지점에서 끊긴다.

## 이미지 (영상·캐러셀 배경) — `worker.py` `_safe_image`, imagegen
- **3단 라우터**: 1순위 Cloudflare **flux-2-klein-4b**(무료) → 실패 시 같은 무료 한도의 flux-schnell → 한도 소진·둘 다 실패면 로컬 RealVisXL 폴백. 한도(4006)는 두 모델이 같은 뉴런 풀을 쓰므로 모델을 바꿔도 안 풀린다 — 그날 CF 경로 전체를 접는다.
- **klein-4b 전환은 2026-08-22 실호출 검증 후다**(`workers/api/scripts/smoke_klein4b.sh`). schnell 보다 한 세대 뒤 모델이라 손·얼굴 기형이 덜하다. 뉴런은 1024² 기준 장당 약 104(schnell 58)로 두 배 가까이 쓰지만 하루 24장이면 무료 한도의 25%다. 되돌리려면 `POPORY_CF_IMAGE_MODEL=schnell` 하나면 된다.
- **생성 치수는 포맷마다 다르다**(klein 만 치수를 받는다) — 롱폼 **1536×1024(3:2)**, 쇼츠 **1024×1536(2:3)**, 캐러셀은 정사각이라 미설정(=1024²). 썸네일은 영상 비율을 따른다. `POPORY_CF_IMAGE_SIZE_LANDSCAPE`/`_PORTRAIT`/`_SQUARE`(`"1536x1024"` 형식, 빈 값이면 모델 기본).
- **한 쌍을 전역으로 쓰면 안 된다** — 가로 3:2 원본을 쇼츠(9:16)에 쓰면 확대율은 1.875x 그대로라 **화질 이득이 0인데** 가로로 63%가 잘려 구도가 무너진다. 포맷별로 줘야 양쪽 다 1.250x 가 된다.
- **3:2·2:3 은 화질과 패닝의 교환이다**(실측 `video._pan_headroom`) — 확대율 1.875x→1.250x 로 33% 선명해지는 대신 패닝 여유가 840→200px 로 준다. 30초 장면 팬은 210→200px 로 거의 그대로고 **53초 장면만 371→200px 로 짧아진다.** 16:9 원본은 여유가 0이라 패닝이 아예 사라지므로 쓰지 않는다.
- **스타일 앵커** — 한 작업의 **첫 검수 통과 이미지**를 480px JPEG 로 줄여 이후 장면·썸네일에 `reference_images` 로 물린다(klein 전용). "전 장면 색감·조명 일관"을 프롬프트 문구가 아니라 모델 입력으로 강제하는 수단이다. 참조만 넣으면 모델이 그걸 재현하려 들 수 있어 프롬프트에 `Match the color grading, lighting and overall mood of image 0.` 를 앞에 붙인다. 앵커는 **첫 장면으로 고정**한다 — 매 장면 덮어쓰면 톤이 서서히 흘러간다. 작업마다 새로 만들어 어제 영상 톤이 오늘로 새지 않게 한다. 끄려면 `POPORY_IMAGE_STYLE_ANCHOR=0`.
- **이미지 안에 글자/텍스트 금지.**
- image_prompt는 영어 한 문장. 기본 스타일 키워드 **`photorealistic, cinematic`** (영상 시리즈에 정해진 룩이 따로 있으면 그것을 우선).
- **인물 정책이 2026-08 뒤집혔다 — 얼굴 허용에서 얼굴 회피로.** 이전엔 "얼굴이 보여도 됩니다"였으나 얼굴·눈·손이 기형으로 나오는 빈도가 높아 정책을 바꿨다. `video_prompt.py`가 이제 **뒷모습·실루엣·원경**을 기본으로 유도하고, 그마저 어려우면 사물·풍경·정물로 대체하게 하며 **정면 얼굴·손 클로즈업을 금지**한다. 근본 대책은 검출이 아니라 "애초에 덜 만들기"다.
- 전 장면 **색감·조명·분위기 일관** 유지 → 한 영상처럼.
- 호출 타임아웃 300초. 깨진 imagegen 응답은 검증·재시도(단색 폴백 사각지대 방지).

### 이미지 이상 검수 (2단 방어) — `image_review.py`, `worker.py` `_safe_image`
1. **생성 전 억제** — 위 프롬프트 정책. 얼굴이 안 나오면 기형도 안 나온다.
2. **생성 후 검수** — `review_image()`가 claude CLI 비전(`--allowed-tools Read`)으로 장당 1회 판정한다. 얼굴 기형·눈 이상(동공 방향·좌우 비대칭·섬뜩한 눈빛)·해부학적 이상(손가락·관절·잘린 몸)·섬뜩한 표정이면 reject.
- **탈락하면 프롬프트를 단계적으로 후퇴시켜 재생성한다**(`harden_prompt`): 1라운드 = 뒷모습·실루엣 강제, 2라운드 = 인물 완전 제거. 같은 프롬프트로 다시 뽑으면 같은 기형이 재현되기 때문이다. 라운드 수는 `POPORY_IMAGE_REVIEW_ROUNDS`(기본 2).
- **끝까지 탈락해도 마지막 이미지를 쓴다.** None을 돌려주면 배경이 단색이 되고 `_finalize_video`가 영상을 failed/review로 떨어뜨린다 — 기형 의심 한 장이 그보다 낫다. 이때 `image_review_exhausted` 로그가 남는다.
- **fail-open이 원칙** — CLI 오류·타임아웃·파싱 실패는 전부 통과 처리한다. 검수는 품질 장치이지 생성 차단 장치가 아니며, 검수 때문에 데일리 배치가 멈추면 안 된다.
- **적용 범위**: 장면 배경, 쇼츠 배경, 캐러셀 슬라이드, **썸네일**까지 전부 `_safe_image`를 거치므로 자동 포함된다.
- **비용·지연**: 장당 claude CLI 1회(타임아웃 90초·2시도). 하루 24장이면 최소 24회 추가 호출이다. 끄려면 `POPORY_IMAGE_REVIEW=0`. 판정 로그는 `image_rejected`(사유·라운드·프롬프트 포함).

## 영상 조립 (기술) — `video.py`
- 켄번스 줌(2x 슈퍼샘플로 떨림 제거), 장면 전환 크로스페이드(xfade/acrossfade).
- **체감을 정하는 건 총 줌 폭이 아니라 초당 속도다** — 폭을 장면 전체에 균등 분산하면 장면이 길수록 느려진다. 롱폼은 장면이 32~53초라 초당 0.19~0.44%까지 떨어져 **정지 화면처럼 보였다**(2026-08-08 확인). 쇼츠(장면 7초, 초당 1.71%)에서만 무빙이 보였던 이유가 이것이다. **쇼츠에서 잘 보인다고 롱폼도 괜찮다고 판단하지 말 것.**
- **왕복(삼각파) 줌** — `ZOOM_RATE_PER_SEC`(0.7%/s)를 고정하고 폭은 길이에서 역산한다(`_zoom_amplitude` = 속도 × 길이/2). 절반까지 갔다 되돌아오므로 **최대 확대율을 묶은 채 속도만 올릴 수 있다.** 한 방향으로만 밀면 인지 가능한 속도에서 총 확대율이 32%까지 커져 1024px 원본이 무너진다. 폭 하한 0.06은 쇼츠 체감(초당 1.71%)을 유지하고, 상한 0.18은 과확대를 막는다.
- **줌 무빙은 장면마다 다르다** — `_MOTIONS` 6종(확대로 시작 여부 × 가로 기준점 0.35·0.50·0.65)을 장면 인덱스로 순회하고, 시작점은 job_id(`zlib.crc32`)로 정해 같은 작업은 항상 같은 결과가 나온다. 인접 항목은 방향이 서로 달라(순환 지점 포함) 같은 무빙이 연달아 붙지 않는다.
- **배경 패닝은 크롭을 덜 하는 것이지 확대를 더 하는 게 아니다** — 원본을 프레임에 커버하면 그만큼 여유가 남는다(`_pan_headroom` — 정사각 1024²는 840px, 기본값인 3:2 1536×1024는 200px). 그만큼 캔버스를 키워 그 안에서 프레임 창을 움직이므로 **확대율이 늘지 않아 화질 손실이 0**이다. 여유가 없는 16:9 원본은 패닝을 걸지 않는다. 패닝은 왕복하지 않고 편도다(확대율을 안 건드려 되돌아올 이유가 없고 같은 여유로 두 배 멀리 간다). 속도 `PAN_RATE_PX_PER_SEC`(7px/s)는 줌 0.7%/s와 체감을 맞춘 값 — 1080px의 0.7%가 초당 7.6px다.
- **필터 순서를 바꾸지 말 것** — `scale`(긴 캔버스) → `zoompan`(s는 **입력과 같은 크기**) → `crop`(프레임 창 이동) → `scale`(출력). zoompan은 입력 종횡비 그대로 크롭하므로 긴 캔버스를 먹이고 s만 16:9로 주면 **화면이 눌린다**. 그리고 **crop을 zoompan 앞에 두면 패닝이 얼어붙는다** — zoompan이 첫 입력 프레임을 d프레임 동안 붙들기 때문(2026-08 ffmpeg 실측, 첫·끝 프레임이 완전히 동일하게 나옴).
- **스크림은 화면 고정 오버레이**(`_render_scrim_png`) — 배경에 구우면 패닝 때 배경과 함께 밀려 자막 뒤가 밝아진다. 오버레이 순서는 스크림 → 헤드라인 → 자막.
- **비용 감각** — 렌더 비용은 수퍼샘플 캔버스 **면적에 정비례**한다. 같은 캔버스 안에서 줌 방향·기준점·폭을 바꾸는 건 공짜지만, 패닝 여유만큼 캔버스가 커지면 딱 그 비율로 느려진다(44.6초 장면 실측 82.4초 → 104.0초, 1.26배 = 캔버스 면적비 1.29와 일치). 용량은 +17%로 maxrate 1200k 상한에 닿지 않아 **재조정 불필요**(11.8분 영상 54MB → 약 63MB, 100MB 한도 안).
- **원본 해상도는 생성기마다 다르다** — 로컬 RealVisXL은 **768×768**, CF schnell 은 1024×1024, CF klein-4b 는 포맷별 지정값(롱폼 1536×1024, 쇼츠 1024×1536, 캐러셀 1024²)이다. **폴백으로 내려가면 해상도가 같이 떨어져** 한 영상 안에서도 장면마다 다를 수 있다. 768이면 1920 가로 기준 2.5배 확대 상태라 줌 폭을 키울수록 화질이 직접 깎인다. 1024로 가정하지 말 것.
- 라이선스-프리 BGM 패드 + 음량 정규화(loudnorm) 마스터 패스.
- 자막은 문장 단위 타이밍, 헤드라인 단일 자막.
- **쇼츠 자막은 YouTube UI 를 피해 올린다** — 재생기가 프레임 하단 약 20%(1920 기준 384px)를 제목·채널명·설명·CTA 로 덮는다. 예전 값(하단에서 305px)은 그 한복판이라 번인 자막과 YouTube 제목이 겹쳐 **둘 다 안 읽혔다**(2026-08-22 업로드분에서 확인, UI 안으로 139px 침범). 지금은 `PORTRAIT_UI_SAFE_BOTTOM`(384) 위로 여백 56px 을 두고 배치한다 — 자막 하단이 1480px, 안전선이 1536px 이다. 가로형은 재생 중 UI 가 숨으므로 175 그대로다.
- **번인 자막은 항상 한 줄** — `_wrap_chunks`가 어절 경계에서 한 줄 길이(가로 30자·세로 18자)로 쪼개고 `_chunk_spans`가 순차 표시한다. 예전엔 문장을 통째로 렌더해 **86%가 2~4줄**이었다(2026-08-08 실측 98개 중 1줄 14%·2줄 57%·3줄 26%·4줄 3%).
- **조각 타이밍은 발화 평문 길이로 나눈다** — TTS는 문장 단위로 합성하므로 문장 *안*은 실측이 불가능해 길이 비례로 추정할 수밖에 없다. 이때 원문이 아니라 `tts.spoken_text`(특수문자 정규화 + 숫자→한글) 길이를 써야 한다. `1,700`은 5글자지만 '천칠백' 3음절로 읽혀 원문 기준이면 그 조각이 과대평가돼 자막이 밀린다. 마지막 조각은 문장 뒤 무음까지 유지해 깜빡임을 막는다.
- **cue(=SRT)는 절대 쪼개지 않는다** — cue는 `_store_subtitles`에서 `translate_lines`로 EN/ZH/JA 번역돼 SRT 4종으로 올라간다. 문장 조각을 번역기에 넘기면 주어·술어가 잘려 번역이 무너진다. **화면 표시용 분할과 cue를 반드시 분리할 것.**
- **자막을 문장 중간에서 쪼개 TTS로 합성하지 말 것** — 조각별 합성은 타이밍은 정확해지지만 문장 중간에 종결 억양과 무음이 생긴다(소수점 분할 사고와 같은 계열).
- 챕터 헤드라인은 68px Bold(가로)·58px Bold(세로), `FONT_INDEX_BOLD`=6(AppleSDGothicNeo.ttc의 Bold face). **검정 외곽선 필수** — 헤드라인은 하단 스크림 밖(좌상단)이라 배경이 밝으면 굵게 키워도 흰 글씨가 그대로 묻힌다(밝은 벽 장면에서 확인).
- **헤드라인 왼쪽에 포포리 책방 로고** — `assets/logo.png`를 `_logo_circle`이 원형으로 마스킹해 얹고, 제목은 로고 오른쪽에 세로 중앙 맞춤으로 그린다. 원본이 **알파 없는 검정 배경 108×108**이라 그대로 얹으면 밝은 장면에서 검은 사각형이 드러나고, 96px보다 크게 쓰면 뭉개진다. 로고 파일이 없거나 깨지면 글자만 그리고 넘어간다(영상 전체를 막지 않는다).
- **렌더 해상도 그대로 내보낸다** — 쇼츠는 1080×1920 으로 렌더한 뒤 **540×960 으로 줄여** 내보냈는데(`PORTRAIT_OUT_W/H`), 유튜브가 폰 화면으로 되키우면서 번인 헤드라인·자막이 눈에 띄게 흐려졌다(2026-08-23 확인 — 같은 화면에서 YouTube 가 그리는 하단 제목은 선명한데 구워 넣은 글자만 뭉갰다). 글리프 가장자리는 고주파라 축소→확대에 가장 먼저 무너진다. **축소는 얻는 것도 없었다** — 용량은 maxrate 가 잡고, 60초 쇼츠는 상한을 다 써도 100MB 한도의 한참 아래다. 지금은 마스터 단계가 항상 `-c:v copy` 라 3세대 인코딩도 사라졌다.
- **인코딩 품질은 포맷별로 갈린다**(`_x264_q`) — 롱폼은 10분까지 가므로 100MB 안에 들어오려면 상한이 빡빡하고(`-crf 28 -maxrate 1200k`), 쇼츠는 60초라 같은 한도 안에서 훨씬 후하게 준다(`-crf 23 -maxrate 6000k` ≈ 37MB). **쇼츠에 롱폼 상한을 쓰면 안 된다** — 1080×1920@30 에 1.2Mbps 면 줌·패닝 모션이 비트를 다 가져가고 정지한 글자 가장자리가 먼저 무너진다. 가로형이 기본 CRF면 긴 영상이 100MB를 넘어 **포털 업로드가 413(Cloudflare 엣지 본문 한도)** 로 실패한다(14분 124MB→69MB). `POPORY_VIDEO_CRF`·`POPORY_VIDEO_MAXRATE`(롱폼), `POPORY_SHORTS_CRF`·`POPORY_SHORTS_MAXRATE`(쇼츠)로 튜닝하며, `-bufsize` 는 maxrate 의 2배로 파생되므로 따로 맞출 필요 없다.

## LLM 모델 — 포털 어드민 `/admin/llm-models`
- **기능별로 고른다** — 블로그·롱폼 대본·쇼츠 대본·캐러셀·커뮤니티 글·댓글 답글·자막 번역·주간 추천·이미지 검수 9개. 카탈로그는 `workers/api/src/lib/llm_catalog.ts` 한 곳에 있고 API 가 어드민·워커 양쪽에 내려준다(목록이 갈라지면 어드민에서 고른 값이 워커에서 안 먹는다).
- **기본값은 `claude-sonnet-5`**(2026-08-23 에 `claude-sonnet-4-6` 에서 올렸다), `POPORY_CLAUDE_MODEL` 로 덮는다. 기본값을 바꾸면 그 값으로 저장돼 있던 기능은 어드민에서 오버라이드로 보인다 — 기본값 선택 시 행을 지우는 설계라 다음 저장에서 정리된다. 어드민에서 기본값을 고르면 행을 지운다 — 남겨 두면 나중에 기본값을 바꿔도 옛 값에 묶인다.
- **워커는 폴 사이클마다 `/api/content/llm-models` 를 읽는다**(TTL 60초, `POPORY_LLM_MODELS_TTL`). 저장하면 **다음 작업부터** 먹고 워커 재시작이 필요 없다. 조회 실패는 삼키고 직전 값(없으면 기본값)으로 계속 간다 — 설정을 못 읽었다고 배치를 멈추지 않는다.
- **호출은 맥미니 claude CLI 를 거친다** — Claude 플랜에 없는 모델을 고르면 그 기능이 `claude CLI exit 1` 로 실패한다. 카탈로그에 있다고 다 되는 게 아니다.
- `POPORY_IMAGE_REVIEW_MODEL` 은 어드민 설정보다 우선한다(현장에서 급히 되돌릴 통로).
- 모델 해석은 `generate.model_for(기능키)` 하나로 모은다. 대본·번역·검수 호출부가 서로 다른 모듈이라 포털 클라이언트를 거기까지 실어 나르면 시그니처만 번진다.

## 신뢰성 / 작업 상태
- claude CLI 일시 실패(parse 실패 등)에 재시도 내성.
- 누락 이미지 비율로 status 결정 — 대부분 실패면 `failed`(재생성 필요), 일부면 `review`+경고.
- 작업 상태 흐름 `queued → running → review/failed`. claim은 `queued`만 집어가고 **`running`에 고아로 남은 작업을 회수하는 lease/timeout이 없다** — worker가 생성 도중 재시작되면 그 작업이 "생성 중"에 영구히 묶인다(직접 `running→queued` 복구 필요). 재발 방지는 미구현.

## 흔한 실수
- 유튜브/쇼츠에 구독·좋아요 CTA를 넣음 (절대 금지인데 LLM이 습관적으로 넣음).
- description 마지막 줄 브랜딩을 빠뜨리거나 문구를 바꿈 (정확히 그대로 넣어야 함).
- 유튜브 장면 narration을 너무 짧게 써서 영상이 설정보다 짧아짐.
- 이미지 프롬프트에 텍스트를 넣거나 얼굴 클로즈업·기형 인체를 유발.
- 코드 수정 후 **worker 재시작을 잊어** 변경이 반영 안 됨 (worker는 장기 상주 프로세스라 모듈을 메모리에 들고 있음).
